---
title: "core-api geplante Jobs"
description: "Inventar der Nest-@Cron-Worker in core-api und wie die Deduplizierung bei mehreren Instanzen auf Cloud Run funktioniert."
---

core-api führt Hintergrund-Sweeps im Prozess über `@nestjs/schedule` aus. Auf Cloud Run können mehrere Instanzen gleichzeitig healthy sein; jeder Job nutzt daher eine **Postgres-Session-Advisory-Lock** mit dem stabilen Cron-`name`. Schlägt `pg_try_advisory_lock` fehl, überspringt diese Instanz den Tick und loggt einmal; der nächste Schedule-Zyklus übernimmt die Arbeit.

Lock-Helfer: `SystemPrismaService.withCronJobLock(jobName, fn)` hält für den gesamten Sweep eine Verbindung aus dem gemeinsamen Runtime-`pg`-Pool, damit Session-Locks nicht fallen, während andere Queries den Pool nutzen (`apps/core-api/src/scheduler/cron-job-advisory-lock.ts`).

## Hinweise zur Idempotenz

Mehrere Jobs tolerieren bereits einen doppelten Tick (bedingte Updates, Row-Claims oder `FOR UPDATE` pro Zeile). Der Advisory-Lock verhindert doppelte **vollständige Sweeps** über Instanzen; mandantenweite Effekte verlassen sich weiterhin auf die bestehenden Guards, wo in Feature-Specs vermerkt (z. B. Notification-Outbox-Claims und Registration-Intake-Byte-Purge).
