---
title: "core-api scheduled jobs"
description: "Inventory of Nest @Cron workers in core-api and how multi-instance dedup works on Cloud Run."
---

core-api runs background sweeps in-process via `@nestjs/schedule`. On Cloud Run, several instances can be healthy at once, so each job uses a **Postgres session advisory lock** keyed by its stable cron `name`. If `pg_try_advisory_lock` fails, that instance skips the tick and logs once; the next schedule picks up work.

Lock helper: `SystemPrismaService.withCronJobLock(jobName, fn)` pins one connection from the shared runtime `pg` pool for the whole sweep so session locks are not dropped while other queries use the pool (`apps/core-api/src/scheduler/cron-job-advisory-lock.ts`).

There are no `@Interval` schedulers in core-api today.

## Idempotency notes

Several jobs already tolerate a duplicate tick (conditional updates, row claims, or `FOR UPDATE` per row). The advisory lock prevents duplicate **full sweeps** across instances; per-tenant effects still rely on those existing guards where noted in feature specs (for example notification outbox claims and registration intake byte purge).
